## Release Summary

NetSentry v2.6.0 is a stable architecture milestone. This release transitions NetSentry from a local IDS-dashboard design into a cleaner **gateway + SIEM model**.

- **NetSentry** → Gateway operations
- **Wazuh** → Alert investigation and security event correlation

---

## Current Architecture

```
NetSentry Gateway
  ├── Debian gateway
  ├── Wi-Fi AP client network
  ├── DHCP service
  ├── AdGuard DNS filtering
  ├── iptables firewall and NAT
  ├── Nginx + Flask HTTPS dashboard
  ├── Suricata IDS
  ├── Wazuh SIEM / investigation dashboard
  ├── Tailscale remote administration
  └── systemd-managed services
```

## Major Changes Since v1.8

### Snort Removed from Active Architecture

Snort was previously deployed as the first NetSentry IDS engine. Earlier versions included:

| Component | Description |
|-----------|-------------|
| Snort AP-side IDS sensor | Active intrusion detection |
| Snort alert_fast.txt output | Alert log output |
| Python Snort alert watcher | Alert monitoring script |
| Structured IDS JSON files | Parsed alert data |
| NetSentry IDS dashboard | Web-based alert viewer |
| Snort service monitoring | Uptime tracking |

**Reason for Removal:** Running Snort and Suricata together created duplicate alerts and noisy investigation output.

> **Note:** All Snort work remains preserved in Git history and historical documentation.

### Active IDS/SIEM Model

| Component | Role |
|-----------|------|
| **Suricata** | Active IDS engine |
| **Wazuh** | SIEM, alert review, correlation, investigation |
| **NetSentry Dashboard** | Gateway operations and status |
| **iptables** | Enforcement and firewall logging |

### Wazuh Integration

Wazuh collects and investigates the following data sources:

- Suricata `eve.json` alerts
- Firewall drop logs
- Nginx access/error logs
- Authentication logs
- System logs
- Journald/kernel events

**Wazuh Dashboard:** `https://192.168.1.19:8443/`

The NetSentry dashboard includes a shortcut/status card for Wazuh.

## Tuning & Optimization

### Suricata Tuning

Rules were tuned to reduce duplicate and noisy alerts:

| Trigger | Expected Alert |
|---------|----------------|
| One AdGuard access attempt | AdGuard-specific alert |
| Repeated SYN behavior | SYN burst alert |
| Repeated administrative probing | Admin probing alert |
| Horizontal AP network scanning | AP scan alert |

This improves Wazuh investigation quality by producing **one meaningful alert per behavior pattern**.

### Firewall Correlation

NetSentry firewall logging uses clear, searchable prefixes:

```
NETSENTRY_FW_INPUT_DROP
NETSENTRY_FW_FORWARD_DROP
```

- Firewall logging is **rate-limited** to avoid flooding logs and Wazuh
- Wazuh custom rules classify NetSentry firewall events

### Performance Tuning

Applied tuning for limited hardware:

| Setting | Action |
|---------|--------|
| Wazuh indexer heap | Reduced to 512m |
| Vulnerability detection | Disabled |
| Syscheck scan-on-start | Disabled |
| Syscheck frequency | Reduced |
| Swap | Configured as safety buffer only |
| Docker/containerd | Disabled if unused |

> ** Swap is used only as a safety buffer. It is not treated as real RAM.**

## Validation Checklist

### 1. Service Status Check

```bash
for s in ssh nginx netsentry-web netsentry-ap-interface hostapd \
         AdGuardHome tailscaled netsentry-firewall netsentry-dnsmasq \
         suricata wazuh-indexer wazuh-manager wazuh-dashboard filebeat; do
  printf "%-32s enabled=%-12s active=%s\n" \
  "$s" \
  "$(systemctl is-enabled "$s" 2>/dev/null || echo not-found)" \
  "$(systemctl is-active "$s" 2>/dev/null || echo not-found)"
done
```

**Expected Result:** All listed services show `enabled=yes` and `active=active`.
